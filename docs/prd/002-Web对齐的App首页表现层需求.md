# 002 Web 对齐的 App 首页表现层需求

- 状态：Accepted
- 日期：2026-08-13
- 最近更新：2026-09-01（移动端首屏信息完整性）

## 1. 用户价值

用户在 App 首屏获得与 Web 一致的产品识别、核心任务层级和链接输入体验，并可提前验证粘贴内容是否为安全的公开 HTTP(S) 地址。服务契约尚未开放时，界面准确说明原因，不让用户误以为任务已经提交。

## 2. 范围

- Web 同源品牌、标题、描述、链接输入、主操作和信任信息。
- 中文与英文、本地 URL 归一化、清空、校验失败和提交不可用状态。
- 固定底部菜单栏与“我的”页深浅主题切换；未来业务页签显示准确未开放状态。
- 390px 手机与较宽设备的原生响应式重排。

## 3. 非目标

- 注册、登录、会话恢复、媒体解析、格式结果、任务创建、历史和平台数据请求。
- 浏览器 Cookie、WebView 登录、远程 SVG、主题持久化或模拟业务数据。

## 4. 产品验收标准

- AC-002-01：首屏内容与 Web 首页当前文案、视觉 token 和操作层级一致。
- AC-002-02：空值、普通文本、多链接、非 HTTP(S) 与含凭据 URL 均不触发提交。
- AC-002-03：分享文本中的单个合法 URL 可被提取、去除末尾标点并传给可注入意图。
- AC-002-04：缺少真实意图时显示契约边界，且没有网络副作用。
- AC-002-05：底部菜单、主题、清空、输入和提交可由键盘/触摸与辅助技术操作。
- AC-002-06：标准手机首屏无需滚动即可看到两条安全提示，Navbar 与主标题之间不保留无效的大段空白。

# PRD 005 API 消费与异常处理需求

## 文档状态

- 状态：Accepted for Planning（2026-07-19）。
- 上游：[Design 005](../design/005-API请求与异常处理设计.md)。
- 输入：FastAPI OpenAPI、统一 envelope、HTTP 状态和 Ant Design Pro 官方请求体系。
- 输出：Service 生成、请求状态、DTO/VO 和全局错误需求。
- 下游：[Plan 005](../plans/005-API消费与异常处理计划.md)。

## 1. 背景与价值

Web 与 Server 独立演进，必须通过服务端 OpenAPI 自动生成请求与类型，并用 Umi 官方能力统一处理网络、业务和页面状态，避免手写契约漂移。

## 2. 产品目标

1. `@umijs/max` Request 是唯一 HTTP 客户端。
2. Umi OpenAPI 插件生成 Service 和 TypeScript DTO。
3. `@tanstack/react-query` 管理 query、mutation、缓存、轮询和取消。
4. `requestErrorConfig` 统一处理 HTTP 与业务错误。
5. 页面只处理与当前操作相关的恢复反馈。

## 3. 非目标

- 不使用手写 Axios Instance、openapi-typescript、第二份 DTO、Redux、Zustand 或 DVA。
- 不加入 GraphQL、SSE、WebSocket、登录跳转或可配置 API Endpoint。

## 4. 业务规则

- 非 `SUCCESS` code 必须由 `errorThrower` 转为业务错误。
- 422 字段错误就地展示；可恢复错误使用 Alert/Result；未知错误使用全局 notification。
- 只有幂等 GET 网络失败自动重试；任务创建 POST 不自动重放。
- 页面不传播 `any`、数据库字段、Celery task ID 或 MinIO object key。
- 原始视频 URL、Header、Cookie、Prompt、密钥不进入日志或错误上报。
- MinIO 文件不使用 JSON envelope，预签名 URL 接口仍使用 envelope。

## 5. 首版验收门禁

- `W005-AC-01`：实际 `/openapi.json` 可生成全部正式 Service，无手工修补。
- `W005-AC-02`：代码不存在第二套 Axios 实例、手写 DTO 或裸请求路径。
- `W005-AC-03`：成功、业务、422、HTTP、超时、断网和未知错误处理符合规则。
- `W005-AC-04`：GET 重试、POST 不重放、取消与轮询行为可测试。
- `W005-AC-05`：页面类型不使用 `any` 绕过 OpenAPI 变化。
- `W005-AC-06`：响应模型没有 `request_id`，只处理 `code/message/data`。
- `W005-AC-07`：敏感输入不进入 URL query、日志、通知或 DOM HTML 注入。

## 6. 待确认问题

无。鉴权加入后再扩展 401/403 行为。

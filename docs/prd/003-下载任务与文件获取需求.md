# PRD 003 下载任务与文件获取需求

## 文档状态

- 状态：Accepted for Planning（2026-07-19）。
- 上游：[Design 003](../design/003-下载任务与文件获取交互设计.md)。
- 输入：下载 job ID、状态、进度、文件元数据和预签名 URL。
- 输出：任务轮询、刷新恢复、文件获取和过期需求。
- 下游：[Plan 003](../plans/003-下载任务与文件获取计划.md)。

## 1. 背景与价值

下载是异步长任务。用户需要离开创建页面后持续看到可靠进度，并能在刷新或短暂断网后恢复，而不是依赖原 HTTP 请求。

## 2. 产品目标

1. 展示 loading、queued、running、succeeded、failed、expired 状态。
2. queued/running 每 2 秒查询，终态、隐藏或离线停止。
3. 页面刷新后通过 job ID 恢复服务端真实状态。
4. 成功后按需获取 MinIO URL 并直接下载。
5. 只有成功且未过期任务提供 AI 入口。

## 3. 非目标

- 不提供任务列表、历史、暂停、取消、原任务重试或格式修改。
- 不由 Web/FastAPI 转发视频文件，不拼接 MinIO 对象地址。

## 4. 状态规则

- queued：0% 与“等待处理”。
- running：服务端 progress、stage 和自动刷新说明。
- succeeded：文件名、容器、大小、过期时间、下载和 AI 按钮。
- failed：安全错误和返回重新提交。
- expired：警告且禁止下载/AI。
- GET 临时失败保留上次数据，不把任务误判 failed。

## 5. 文件规则

- 点击下载时才请求预签名 URL。
- URL 获取失败不改变 succeeded，可再次获取。
- 页面同时区分文件过期时间和本次 URL 有效期。
- 浏览器直接访问 MinIO；Web 不知道 Bucket 或 object key。

## 6. 首版验收门禁

- `W003-AC-01`：六种状态和未知状态安全分支均有组件测试。
- `W003-AC-02`：轮询仅在 queued/running 可见在线时运行，间隔 2 秒。
- `W003-AC-03`：刷新、前进、后退可凭 job ID 恢复，不依赖内存伪状态。
- `W003-AC-04`：GET 临时失败保留数据并允许恢复。
- `W003-AC-05`：文件 URL 按需获取、可再次获取且直接交给浏览器。
- `W003-AC-06`：failed/expired 不显示无效下载或 AI 操作。
- `W003-AC-07`：进度和终态对键盘、屏幕阅读器和手机布局可用。

## 7. 待确认问题

无。任务列表和取消功能不属于首版。

# 016 原生文件上传与媒体组件体验需求

## 用户需求

1. 下载详情中的可支持视频必须能够直接播放，并提供符合移动端习惯的完整控制。
2. 不受设备编解码器支持的格式必须准确说明原因并允许获取原文件，不能呈现失效播放按钮。
3. AI 分析类型、输出语言和结果分区必须使用一致且有界的选择组件。
4. 超长媒体标题不得占据大部分屏幕，最多展示三行并使用省略号。
5. 首页必须能够选择并上传本地 MP4 视频，以及 DOCX、PDF、TXT、Markdown、Fountain 剧本文档。
6. 上传必须显示阶段与进度，失败可理解，成功后进入真实下载详情或剧本文档列表。
7. 客户端必须复用服务端 OpenAPI 上传会话，不得维护平行 DTO 或把 Bearer Token 发送给对象存储。

## 验收标准

- AC-016-01：MP4/H264 显示开源播放器控制层，播放失败显示明确错误。
- AC-016-02：iOS WebM/VP9/AV1 继续显示不支持说明和获取文件操作。
- AC-016-03：三个 AI 选择场景不再使用 `DropdownButtonFormField`，菜单最大高度受控。
- AC-016-04：下载详情标题使用较小字号、三行上限和省略号，语义标签保留完整标题。
- AC-016-05：系统选择器允许 MP4 与五类剧本文档，取消选择不显示错误。
- AC-016-06：上传执行流式 SHA-256、受限 multipart PUT、ETag 校验和完成请求，并显示 0–100% 进度。
- AC-016-07：Android Debug 与 iOS Simulator 构建、静态分析和测试通过。

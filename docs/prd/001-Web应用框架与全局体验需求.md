# PRD 001 Web 应用框架与全局体验需求

## 文档状态

- 状态：Accepted for Planning（2026-07-19）。
- 上游：[Design 001](../design/001-Web边界与总体架构设计.md)。
- 输入：Ant Design Pro/Umi Max 全套技术栈和单链接主流程。
- 输出：Web 工程、路由、布局、响应式和全局体验需求。
- 下游：[Plan 001](../plans/001-Web应用框架与全局体验计划.md)。

## 1. 背景与价值

Web 需要以官方 Ant Design Pro 工程为唯一基础，使路由、布局、请求、状态、组件和测试保持一致，避免在完整脚手架外再维护一套自建前端架构。

## 2. 产品目标

1. 使用 Ant Design Pro/Umi Max 官方脚手架和默认工程能力。
2. 提供下载工作台、下载任务、AI 任务三类页面及 404。
3. 使用 ProLayout 顶部布局、中文 Locale 和 Ant Design Token。
4. 页面在桌面、平板和手机可完成完整主流程。
5. 全局状态、服务端状态和页面状态职责清晰。

## 3. 非目标

- 不建设登录、用户中心、Dashboard、运营后台、复杂菜单或自定义组件库。
- 不引入 Redux、Zustand、DVA、手写 Axios 实例或空白 Vite 架构。
- 不在本需求实现具体解析、下载或 AI 业务内容。

## 4. 用户故事

- 作为用户，我希望进入应用后直接看到视频下载入口，而不是后台模板示例页。
- 作为手机用户，我希望不横向滚动即可完成输入、查看进度和下载。
- 作为键盘用户，我希望主流程控件具有可见标签、焦点和状态反馈。
- 作为维护者，我希望服务端数据不被复制进 Umi Model。

## 5. 业务规则

- `/` 重定向 `/download`；下载和 AI 详情为隐藏菜单路由；未知路径显示 Pro Result 404。
- 只有“视频下载”一个主菜单，不保留脚手架演示页面。
- Umi Model 只保存客户端全局状态；React Query 保存服务端状态。
- 默认语言为 `zh-CN`；MVP 路由公开，但保留 Umi Access 官方能力。
- 动态状态不能只用颜色表达，不能自动抢焦点。

## 6. 首版验收门禁

- `W001-AC-01`：工程基于官方 Ant Design Pro/Umi Max，可安装、测试、类型检查和构建。
- `W001-AC-02`：正式路由、重定向、隐藏菜单和 404 行为符合 Design。
- `W001-AC-03`：不存在示例 Dashboard、登录、用户中心或无业务空白页。
- `W001-AC-04`：ProLayout、中文 Locale、Token 和 1200px 内容边界生效。
- `W001-AC-05`：桌面、平板、手机及键盘主流程基础布局可用。
- `W001-AC-06`：不存在 Redux、Zustand、DVA、手写 Axios Instance 或第二套状态架构。

## 7. 待确认问题

无。登录和多语言内容需要独立 Design/PRD。

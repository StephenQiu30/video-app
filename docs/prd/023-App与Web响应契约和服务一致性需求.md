# App 与 Web 响应契约和服务一致性需求

状态：Accepted。日期：2026-09-21。

1. App 必须能够读取当前服务端统一 `{code, message, data}` 响应，下载记录不得因客户端契约过期而失败。
2. App 冻结契约、生成客户端与当前服务端 OpenAPI 必须同步；生成目录不得手工修补。
3. Repository 必须解包并校验业务 `data`，向 application / presentation 只返回业务模型。
4. 原生认证直接响应必须保持可用，不得误套共享业务包装。
5. 服务端的 `message` 必须进入失败映射；旧 `detail` 只作兼容回退，响应内容和凭据不得写入日志。
6. 网络不可达、未登录、无权限、限流、服务错误和响应不合法必须显示不同语义；契约错误不得提示“检查网络连接”。
7. 下载历史成功态应与 Web 保持数据和能力一致：摘要、搜索、状态筛选、分页、详情入口及允许的任务操作均可用；移动端保留底部导航、手势和安全区。
8. 持久页面错误必须可见、可访问、可重试；已有数据刷新失败不得清空旧数据。
9. 修改须覆盖契约生成检查、Repository/错误映射测试、全量 Flutter 静态检查和测试，并尽可能在 iPhone 17 Pro 模拟器验证真实服务成功态。
10. 验收必须分别说明代码/测试、模拟器、真机和真实 Provider 链路边界，不能以其中一项推断全部通过。

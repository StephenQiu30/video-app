# 017 用户内容删除与 Web 文案同步需求

## 用户需求

1. 用户可以从下载记录列表和下载详情删除自己创建的任务及关联私有文件。
2. 用户可以从剧本文档列表删除自己上传的剧本及关联规范化内容。
3. 删除前必须明确展示影响范围并二次确认；活动下载可由服务端先取消，活动分析锁必须阻止删除。
4. 删除失败不得让记录从界面消失；成功后列表和详情必须立即反映真实服务端状态。
5. App 的下载记录、剧本文档、状态和删除文案必须与 Web 当前普通用户页面保持一致。
6. App 必须通过冻结 OpenAPI 生成客户端调用删除接口，服务端负责 owner 授权和对象存储清理。
7. 下载和剧本文档列表通过一致的左滑操作显示删除，不常驻显眼垃圾桶；界面必须提供可发现提示和等价的辅助功能动作。
8. 服务端因活动分析锁拒绝删除时，App 必须说明需要先结束相关分析，并保留原记录。

## 验收标准

- AC-017-01：下载列表和详情均存在删除入口，确认后调用 `DELETE /api/downloads/{job_id}`。
- AC-017-02：剧本文档列表存在删除入口，确认后调用 `DELETE /api/documents/{document_id}`。
- AC-017-03：取消确认不发请求；请求失败保留内容并显示错误；成功后刷新列表或安全返回。
- AC-017-04：活动下载提示会先取消；剧本文档提示活动分析需先结束。
- AC-017-05：中文下载/文档说明、空状态和业务状态与 Web 一致，英文语义完整。
- AC-017-06：Flutter 分析、测试、Android Debug 与 iOS Simulator 构建通过。
- AC-017-07：列表默认不显示危险按钮，左滑后操作可点击，屏幕阅读器可直接触发同一确认流程。
- AC-017-08：`409 invalid_state` 显示可行动的占用提示，且不会从列表移除资源。

# 019 剧本文档详情与跨端一致性设计

## 目标

补齐 App 的剧本文档详情链路，使已解析条目可以从列表或深链接进入详情，并与 Web 共用同一份文档、解析和剧本分析数据。跨端一致性指信息、状态、操作与结果一致；布局继续采用各平台适合的响应式组件。

## 数据与路由

- OpenAPI 生成边界增加文档详情、创建文档分析和读取最新文档分析三个操作，总计 47 个受审操作。
- `/documents/:documentId` 是 App 的类型化详情路由；列表整行提供点击、读屏提示和独立删除语义。
- 详情 Provider 在 `uploading`、`verifying` 阶段每 3 秒轮询，进入终态后停止；刷新和删除仍使用同一仓储。
- 分析控制器以 `AnalysisTarget` 区分视频与剧本，复用状态机、重试、取消、删除和报告预览。

## 表现层

- 详情展示状态、文件名、格式、语言、场景数、字符数、导入版本、文件大小、时间、解析摘要和规范化正文。
- 手机宽度的长指标采用两列，避免 `FOUNTAIN` 等值被截断；大屏恢复四列。
- Markdown 正文转义 HTML 标签、禁止链接跳转并保持可选择；明暗主题使用现有无边框视觉系统。
- 剧本分析完成后展示故事概览、结构、人物、场景、对白、修改建议和完整 Markdown 报告；终态不再显示“等待调度”。

## 服务一致性

- Web 浏览器上传通过同源 `/storage-upload` 路由转发到现有预签名 MinIO 地址，解决浏览器无法直连 Tailscale 对象存储的问题；App 保持原生直传。
- 转发路由仅接受现有 MinIO 公网端点的 AWS4 预签名地址，不允许任意目标，且不读取或改写环境文件。
- 剧本分析读取器允许导入 Worker 写入的 `scenes` 与 `parse_summary` 组合，同时继续拒绝未知顶层元数据。

## 验证策略

单元与 Widget 测试覆盖路由、轮询、跨输入类型分析和窄屏指标；真实生产验收覆盖 Web 上传、App 详情、剧本分析、明暗主题和测试数据清理。浏览器使用 `agent-browser`，最终补充只读 `review-agent` 审查。

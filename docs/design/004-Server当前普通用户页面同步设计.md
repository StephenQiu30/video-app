# 004 Server 当前普通用户页面同步设计

- 状态：Accepted
- 日期：2026-08-27
- Server 基线：`video-server` `8bb2e91`
- 用户决策：App 页面随当前 Server 普通用户能力更新，同时继续遵守原生契约边界

## 1. 对齐范围

本次同步 `video-server` 当前普通用户页面的信息架构，不复制 Web 组件实现：

- 首页从单一视频链接入口升级为“链接解析 / 本地视频 / 剧本文档”三种素材入口。
- 链接入口说明公众号文章多视频发现与显式选择、公开视频号单作品解析等当前能力。
- 一级导航升级为首页、下载记录、剧本文档、平台状态与我的五个目的地。
- 下载记录页面明确覆盖任务恢复、失败原因、完成后视频预览、文件获取与 AI 分析入口。
- 剧本文档页面明确覆盖导入状态、规范化预览、分析与改写结果。
- 平台状态页面区分接入状态、访问模式、最近状态检查、真实下载证据与完整分析证据。

管理员分析、文件管理、平台目录、AI 服务和用户管理继续只属于 Web 管理端。

## 2. 原生呈现

- 使用 Flutter Material 3、安全区、系统返回和底部导航；不嵌入 WebView。
- 首页三种素材入口使用无卡片的原生分段切换，保持输入和选择状态。
- 尚未具备原生上传/会话契约的入口显示准确的能力说明和待接入反馈，不提供失效控件或模拟结果。
- 五项底部导航在 390×844 基线下保持可读、可点击并保留首页状态。
- 页面继续使用同源 Logo、语义色、6px 圆角、连续内容流和系统字体。

## 3. 契约边界

`video-server` 当前仍以浏览器 HttpOnly Cookie 会话服务 Web。App 不抓取 Cookie、不复用 WebView 登录、不手写远程 DTO，也不把 Web 接口直接当成已冻结的 App 契约。

因此本次交付只更新页面信息架构、本地输入校验、切换状态、可访问性语义和契约阻塞反馈。公众号发现、视频号解析、上传、下载预览、文档列表与平台证据等真实数据必须等待 App 专用 OpenAPI、原生会话和文件契约冻结后接入。

## 4. Design Acceptance Criteria

- DAC-004-01：首页显示三种当前素材入口，链接入口可接受分享文案中的单个 HTTP(S) URL。
- DAC-004-02：底部导航与 Server 普通用户一级页面一致，共五个目的地。
- DAC-004-03：下载记录、剧本文档和平台状态准确描述 Server 当前能力，不展示模拟数据。
- DAC-004-04：所有未冻结远程动作 fail closed，并说明原生契约阻塞。
- DAC-004-05：390×844、深浅主题、动态文字和屏幕阅读器语义继续满足现有门禁。

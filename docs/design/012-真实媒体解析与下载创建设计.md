# 012 真实媒体解析与下载创建设计

- 状态：Accepted
- 日期：2026-08-31

## 1. 目标

使用当前 `video-server /openapi.json` 的 `NativeBearerAuth` 契约完成 C 端核心链路：公开视频或公众号文章链接输入、来源发现、媒体解析、格式选择、创建下载和进入任务详情。链接入口同时接受包含唯一 HTTP(S) URL 的平台分享文案，提交服务端前提取并清理该 URL。删除此前只展示“契约尚未冻结”的空实现。

## 2. 唯一契约

App 只通过生成客户端调用当前接口，不保留旧占位、手写 DTO、Web Cookie、WebView 或双轨兼容分支：

- `POST /api/source-discoveries`：公众号文章候选视频发现。
- `GET /api/source-discoveries/{discovery_id}`：恢复来源发现结果。
- `POST /api/inspections`：公开链接或已选候选项解析。
- `GET /api/inspections/{inspection_id}`：读取解析资源。
- `POST /api/downloads`：使用解析 ID 与格式 ID 创建任务。

所有 POST 使用一次用户意图对应的稳定 `Idempotency-Key`。Access Token 继续只由 `AuthenticatedRequest` 写入生成客户端；401 只执行既有单飞刷新与一次重放。

## 3. 状态与交互

- 普通公开链接直接解析；`https://mp.weixin.qq.com` 文章先执行来源发现，多候选时由用户明确选择后再解析。
- 输入变化立即清除旧解析、旧候选、选中格式和旧错误，避免跨 URL 误提交。
- 链接输入支持直接 URL 或整段平台分享文案；只接受恰好一个 HTTP(S) URL，多个 URL 的文案继续拒绝，避免误解析。
- 解析中、候选选择中和创建任务中互斥；忙碌期间禁止重复提交。
- 解析成功展示服务端封面、标题、平台、时长和全部语义格式；默认选中服务端返回的第一项，用户可改选。
- 格式不在客户端筛选或改写；与 Web 一致放入最高 `360px` 的独立滚动区域，使创建操作不被长格式清单推离当前结果区。
- 仅 `access_decision == downloadable` 时允许创建下载；其他决策直接显示服务端 `user_action` 或 `restriction_reason`，不猜测、不降级。
- 创建成功后使历史数据失效并直接进入 `/downloads/{jobId}` 详情，由详情页显示真实队列与进度。
- 详情页只在 `queued`、`running`、`retry_wait` 状态下每 2 秒读取当前资源，进入成功、失败或取消终态后立即停止轮询。

## 4. 错误与超时

- 客户端 URL 校验只负责拒绝空值、非 HTTP(S)、凭据 URL 和多链接；解析能力以服务端结果为准。
- 解析请求使用 185 秒接收超时，完整覆盖服务端 180 秒请求预算；不在 UI 层自行重试或切换接口。
- 401、403、429、网络不可用与服务端 Problem Details 映射为明确错误；错误不清除用户输入。

## 5. 边界

本设计解决链接解析与下载创建，不引入本地文件上传、剧本文档上传、WebSocket 或 AI 分析。那些能力必须各自使用当前正式契约实现，不能作为本链路的兼容 fallback。

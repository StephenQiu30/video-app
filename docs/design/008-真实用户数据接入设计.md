# 008 真实用户数据接入设计

- 状态：Accepted
- 日期：2026-08-30
- 上游契约：`video-server /openapi.json`

## 目标

登录后的历史、文档和平台状态页面读取当前用户与服务端的真实数据，移除“尚未开放”占位内容。真实空集合显示空状态，网络或服务失败显示可重试错误，不能退回 Mock 数据。

## 契约边界

- `GET /api/downloads/history`：当前用户下载任务、分页信息与汇总。
- `GET /api/documents`：当前用户剧本文档与处理状态。
- `GET /api/providers`：服务端公开的平台能力快照，不包含账号、Cookie、出口或探针地址。
- 三个端点均使用原生登录签发的 `NativeBearerAuth`；Access Token 只在内存中注入请求。
- 收到 `401` 时只执行一次 Refresh Rotation 并安全重放 GET；刷新失败由既有认证门禁清理会话并返回登录。

## 客户端结构

- App 专用 OpenAPI 工具参考 Umi OpenAPI 的声明式来源配置：单一 Dart 入口读取 Swagger，只新增上述三个只读端点及传递依赖模型，再由固定版本生成器产生 Dio 客户端，不使用多段 Shell 拼接。
- 功能数据层统一负责 Token 注入、一次刷新、错误归类与生成客户端调用；页面不直接访问 Dio。
- Riverpod `AsyncNotifier` 分别管理下载历史、剧本文档和平台状态；首次切换到页面时加载，保留成功数据并支持下拉刷新。
- 历史与文档首期读取第一页 20 条，界面展示服务端返回的总数；继续分页在独立需求中实现，不能暗示已加载全部数据。

## 表现与状态

- 延续无边框、连续画布和 Lucide 图标语言，不恢复卡片外框、Tab 选中短横线或重复的首页入口。
- 页面覆盖初始加载、成功、真实空集合、请求失败、重试与刷新；成功列表只显示契约中存在的字段。
- 状态文本、时间、文件大小和能力枚举由客户端本地化；未知枚举使用安全的通用文案，不泄露原始错误细节。
- 列表行提供合适的标题、状态与组合 Semantics；刷新控件和重试动作具备可读标签。

## 非目标

- 不在本轮创建、删除、下载文件、重试任务、上传文档或接入 WebSocket。
- 不修改 `video-server`，不读取浏览器 Cookie，不持久化 Access Token。

# API 消费与无障碍契约设计

## 1. API 与身份边界

`video-server/openapi/openapi.json` 是认证与领域 HTTP 的唯一事实来源。前端通过 `openapi-typescript` 生成 transport types；Backend for Frontend（BFF）自身的 `LOCAL_*` Problem 只由版本化 `schemas/local-problem.schema.json` 定义，不冒充 server envelope。

浏览器只调用当前同源的 `/api/video/v1/*`；生产环境 public origin 必须使用 HTTPS，开发环境只允许 accepted 认证契约明确测试的本地 origin。BFF 校验固定 public origin、Host 和内部 API authority，再透传 method、JSON、Cookie、`X-CSRF-Token`、`Idempotency-Key`、`Last-Event-ID`、content type、Retry-After 和 `X-Request-ID`。它把上游相对 `Location: /api/v1/*` 重写为同源 `/api/video/v1/*`。浏览器不跨源调用 Server，因此不启用 credentialed Cross-Origin Resource Sharing（CORS）。

BFF 启动配置只允许一个 Cookie profile：production HTTPS 精确透传 `__Host-video_session`/`__Host-video_csrf`；显式 loopback development 精确透传 `video_session_dev`/`video_csrf_dev`。非 loopback dev、两组名称混用或未知 Cookie 均 fail closed；BFF 不解释 Cookie 值，也不把它们写入 JSON、页面属性或客户端状态。专用 CSRF bootstrap JSON 中的 raw token 原样返回浏览器内存；不安全方法要求精确 Origin、`Sec-Fetch-Site: same-origin`、`X-CSRF-Token` 和契约 content type。BFF 先执行同源门禁，Server 再用 fastapi-csrf-protect 验证 HttpOnly 签名 Cookie、raw header 与 1 小时有效期；两层任一失败都拒绝请求。

BFF 自身错误固定为 `{type:"about:blank",title,status,code,detail,request_id}`：公共 origin 或 API authority 缺失为 503 `LOCAL_CONFIGURATION_ERROR`，Server 不可达为 503 `LOCAL_SERVER_UNAVAILABLE`，边界拒绝为 403 `LOCAL_REQUEST_REJECTED`；content type 为 Problem JSON 并返回 `X-Request-ID`。

BFF 使用按 Plan 审核的精确 method/path allowlist，不提供 catch-all 代理。Plan 000 只开放 accepted 认证 OpenAPI 所需路径；Plan 001 再追加 current rights、Resolution、Source 和 Job SSE 路径。路径 decode 一次后拒绝 `..`、encoded slash、额外 segment、其他 method 与未解锁 endpoint，拒绝请求不转发 Cookie 或 CSRF token。

## 2. 邮箱身份与会话生命周期

Server 负责邮箱规范化、密码哈希、验证状态、撤销和审计，并以 PostgreSQL DatabaseStrategy 持久化会话。Web 不实现备用身份表、JSON Web Token（JWT）签发或“记住我”token。生产 `__Host-video_session` 必须为 `HttpOnly`、`Secure`、`SameSite=Lax`、`Path=/` 且无 `Domain`；loopback-only `video_session_dev` 保持除 Secure 外的同等属性。过期、撤销与 profile 规则由 accepted Server 认证契约冻结。

认证流程包括注册、验证邮件、重发验证、登录、退出、忘记密码、重置密码和当前用户投影。忘记密码与重发验证使用不暴露账号是否存在的统一完成提示。未验证账号不能进入工作台，并提供受限的重发验证动作；限流显示 Server 提供的安全重试时间。

Server 通过 `GET /api/v1/auth/csrf` 为预认证和已认证流程返回 `{csrf_token}`、`Cache-Control: no-store` 并签发 `HttpOnly` 配对 Cookie；Web 同源路径为 `GET /api/video/v1/auth/csrf`。Web 只在内存中保存 raw token，并在登录、注册、退出、重置和所有领域 mutation 的 `X-CSRF-Token` header 中发送。首次提交、1 小时过期、刷新丢失内存值，以及登录/注销/重置清除配对后都重新 bootstrap；失败动作不能自动重放，必须要求用户再次触发。

验证和重置链接的一次性 token 只能放在 `/verify-email#token=…` 或 `/reset-password#token=…` 的 URL fragment。fragment 不进入 HTTP 请求或 Referer；Client Component 读取值后必须先用 `history.replaceState` 清除 fragment，再通过同源 BFF POST 交换。token 禁止进入 query string、浏览器历史、SSR HTML、Web Storage、日志、console、遥测或第三方请求；认证页不加载第三方资源。

`AuthShell` 只消费 Server 返回的安全用户投影。未认证或已撤销会话会清空用户相关 Query cache 并进入登录页；退出成功执行同样清理。`next` 只接受站内相对路径和明确受保护路由，拒绝协议、主机、双斜杠和编码绕过。

## 3. 幂等与表单快照

页面按当前 UI locale 读取 server current statement 并展示正文。用户填写 URL 后确认权利，提交时才为 `{url,rights_confirmed:true,rights_statement_version,rights_statement_locale}` 生成 key。同一次 transport retry/页面恢复复用 key；URL 编辑或取消确认会清空确认、旧 key、resolution 和 format。终态失败后用户明确“重新探测”会生成新 key；一般幂等 409 也要求新 key。

若 GET 与 POST 之间声明升级，server 返回 `RIGHTS_STATEMENT_STALE`：Web 必须丢弃旧 key 和确认、重新 GET current、确认正文/hash/version 已更新后把焦点移到新声明标题，并要求用户再次勾选；不得自动确认或盲目重放。unsupported locale 提供切换到 `zh-CN/en-US`，statement unavailable 保留输入但禁用提交。

浏览器校验只提供格式提示；服务端决定安全、policy 和错误。Plan 001 不向任何接口提交 `format_key`，只把选中 key 写入 query state。

## 4. Transport 与 View Model

生成 transport 保持 `snake_case`。显式纯函数 `toSourceView` 转换为 camelCase UI model；它是展示模型，不重新声明 HTTP envelope，输入类型必须来自生成文件。

Source 展示 `title/platform/duration_seconds/policy/resolved_at/expires_at`，不展示缩略图。Variant 映射服务端全部字段；nullable 值显示“未知”，`has_audio/has_video/requires_merge/size_is_estimate/recommended` 不可空。排序与推荐使用服务端顺序，前端不得重新推断未知值。

## 5. 状态与事件映射

| Server | View | 文案 |
| --- | --- | --- |
| `QUEUED` | `queued` | 已进入解析队列 |
| `RUNNING` | `probing` | 按 canonical stage 展示校验/政策/元数据/格式 |
| `RETRY_WAIT` | `retrying` | 上游暂时不可用，正在有限重试 |
| `SUCCEEDED/READY` | `resolved` | 已读取真实规格 |
| `FAILED` | `failed` | 按 canonical error 显示动作 |

使用 fetch-based SSE 连接同源 BFF，以 wire `id` 为 cursor；先以 `/^(0|[1-9][0-9]*)$/` 校验，再用 `BigInt(event.id) <= BigInt(cursor)` 丢弃重复/乱序，绝不使用 string/Number 比较。断开后显式携带 `Last-Event-ID` 指数退避，超过 3 次改为 2 秒轮询 Resolution。`stream-reset` 或 `INVALID_EVENT_CURSOR` 立即清 cursor 并 GET snapshot；终态事件也必须 GET snapshot。刷新从 `resolution` query 恢复，不创建新 Job。

## 6. canonical 错误体验

| Code | 用户动作 |
| --- | --- |
| `AUTHENTICATION_REQUIRED` | 清除用户缓存，显示会话失效并进入登录页；不自动重放 mutation |
| `REQUEST_ORIGIN_REJECTED` | 显示请求安全边界错误并停止提交 |
| `IDEMPOTENCY_KEY_REQUIRED`, `IDEMPOTENCY_KEY_INVALID` | 清理本地 key，显示客户端契约错误与支持 ID |
| `CONTENT_TYPE_UNSUPPORTED` | 显示客户端/服务端契约不匹配 |
| `RESOURCE_NOT_FOUND` | 清除不可恢复的 query resource 并返回输入态 |
| `RIGHTS_CONFIRMATION_REQUIRED` | 聚焦确认项，不创建任务 |
| `RIGHTS_LOCALE_REQUIRED`, `RIGHTS_LOCALE_UNSUPPORTED` | 提供切换到 `zh-CN` 或 `en-US` |
| `RIGHTS_STATEMENT_STALE` | refetch 新正文，清确认/key 并要求再次确认 |
| `RIGHTS_STATEMENT_UNAVAILABLE` | 保留 URL、禁用提交并允许重试声明加载 |
| `INVALID_URL` | 聚焦 URL 并说明格式 |
| `UNSAFE_URL` | 说明只接受公开安全来源 |
| `IDEMPOTENCY_CONFLICT` | 清理旧 key 后由用户重新提交 |
| `SOURCE_UNSUPPORTED` | 查看当前支持来源 |
| `SOURCE_POLICY_BLOCKED` | 展示 policy 与经过验证的官方动作 |
| `SOURCE_DOWNLOAD_DISABLED` | 说明创作者未开放下载 |
| `SOURCE_DRM_UNSUPPORTED` | 明确不提供 DRM 绕过 |
| `SOURCE_AUTH_REQUIRED` | 明确不导入 Cookie 或账号 |
| `SOURCE_RATE_LIMITED` | 展示可空重试等待时间 |
| `SOURCE_TIMEOUT`, `SOURCE_UPSTREAM_FAILED` | 说明有限重试与重新提交 |
| `SOURCE_SNAPSHOT_EXPIRED` | 清除旧 format，生成新 key 后重新探测 |
| `QUEUE_DELIVERY_FAILED` | 说明本地队列投递失败，保留支持 ID |
| `INVALID_EVENT_CURSOR` | 清 cursor、GET snapshot 并继续轮询 |
| `INTERNAL_ERROR` | 显示安全通用错误和支持 ID |
| `LOCAL_CONFIGURATION_ERROR`, `LOCAL_SERVER_UNAVAILABLE`, `LOCAL_REQUEST_REJECTED` | 显示本地配置、服务或请求边界错误 |

accepted 认证 OpenAPI 中的邮箱、验证、会话、限流和 CSRF canonical code 必须全部映射，Plan 000 进入 `ready` 前把精确列表写入 Acceptance。Web 不为尚未 accepted 的 Server code 创建本地别名。

未知错误显示通用文案，不展示供应商原始消息。支持 ID 的唯一优先级是：异步失败显示持久化 `error.correlation_id`；Server 同步 Problem 显示该响应 `X-Request-ID`；LOCAL Problem 显示经 schema 验证且与 header 相同的 body `request_id`。承载 GET/SSE 的 request ID 不能覆盖 worker correlation ID。异步 `error` 与同步 Problem Details 使用同一 code 映射，但分别按上述来源取支持 ID。

## 7. 焦点、状态与键盘

- 认证字段使用正确的 `type`、`autocomplete`、可见 label 和关联错误；提交结果进入可聚焦状态摘要。
- URL 和确认项有可见 label；错误通过 `aria-describedby` 关联。
- 提交后焦点到状态标题；成功到结果标题；失败到错误摘要。
- stage 变化使用节流 `aria-live="polite"`，不播报 heartbeat 或每次 tail。
- Variant 使用原生 radio；桌面规格表有 scope 表头，移动卡保持同一 radio group。
- 所有操作键盘可达、焦点可见、目标至少 44×44 CSS px；颜色不作为唯一信号。
- `prefers-reduced-motion` 下禁用扫描/位移，保留即时状态更新。

## 8. 响应式验收语义

- 375 px：单列、无页面横向滚动、主操作不遮挡内容。
- 768 px：分区切换无重叠、裁切或焦点丢失。
- 1440 px：Plan 001 的输入控制区与解析结果区形成 5/7 结构，规格表可完整比较；知识内容区到后续 Plan 才启用。
- 200% 缩放：文本、焦点和操作不丢失；长标题、多语言、null 字段和完整错误不溢出。

## 9. 安全与隐私

服务端文本按不受信内容渲染，禁止 `dangerouslySetInnerHTML`。`official_url/open_official` 只允许 HTTPS，并以 `noopener noreferrer` 新开。Plan 001 不请求第三方缩略图、字体或分析脚本。

安装令牌、浏览器 Bearer token 和独立 session token 不属于 Web 现行契约。当前 profile 的会话/CSRF Cookie 值不得出现在 JavaScript 可读内容、bundle、HTML、DOM、Web Storage、日志、console 或遥测；它们只允许存在于浏览器 Cookie jar 和预期同源请求。CSRF raw token 只允许短暂存在于专用 no-store bootstrap JSON、内存和 `X-CSRF-Token` header，禁止 URL、HTML、Web Storage、日志、console 或遥测。验证和重置 token 只允许短暂存在于 fragment、内存和交换请求正文。

源站媒体 URL 和 selector 禁止出现在 bundle、HTML、DOM、storage、network、console 或 telemetry。用户 source URL 只允许出现在受控输入 DOM 与预期同源 BFF POST body，禁止进入 SSR HTML、storage、日志、console、telemetry 和非 BFF 请求。

## 10. 验证

- Testing Library：认证字段、防枚举反馈、安全返回目标、会话过期、label、描述、焦点、live region、radio/table 和 reduced motion。
- Playwright：Cookie 属性、退出撤销、跨主体缓存、CSRF 缺失/篡改/过期/跨站、一次性 token 清理、刷新、断网、SSE 重复/乱序/reset/轮询、三视口、200% 和纯键盘。
- MSW fixture 必须由已接受 OpenAPI 生成，覆盖所有 Plan 001 code、状态与 nullability。
- axe 无 serious/critical；人工按 Plan 001 WCAG 2.2 AA checklist 逐项记录。
- Chromium 固定 profile 下运行 30 次，从点击提交到结果标题和首个 radio 完成渲染计算 p95；另按 Acceptance 的 Lighthouse user-flow profile 计算入口 CWV p75。

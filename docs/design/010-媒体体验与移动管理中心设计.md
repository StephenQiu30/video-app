# 010 媒体体验与移动管理中心设计

- 状态：Accepted
- 日期：2026-08-30
- 对齐基线：`video-server` Web 下载详情、下载记录与管理员页面

## 目标

让 Flutter 下载记录和详情使用与 Web 相同的真实媒体资源：私有封面、短时播放地址和短时文件下载地址；同时为管理员提供适合移动端的高频运营入口，而不把浏览器管理台机械缩小到手机屏幕。

## 媒体展示与操作

- 历史列表采用 Web 相同的“16:9 封面 + 标题/来源/格式 + 状态/动作”信息层级，继续使用无边框连续画布。
- 封面路径只允许服务端返回的 `/api/inspections/{id}/thumbnail` 与 `/api/downloads/{id}/thumbnail`，通过生成客户端和原生 Bearer 会话读取为内存字节；不把 Token 写入图片 URL。
- 成功且文件仍可用时，详情顶部使用原生视频播放器；播放器和文件下载都先调用 `POST /api/downloads/{job_id}/download-url` 获取短时 URL。
- “观看”在应用内播放，“获取文件”交给系统浏览器处理带 `Content-Disposition: attachment` 的短时地址，使 iOS 保存到“文件”、Android 使用系统下载能力。短时 URL 不持久化、不记录日志。
- 非成功任务显示封面、状态和进度；已完成但文件被清理时不展示无效操作。

## 移动管理中心

- 仅当原生会话 `UserResponse.role == admin` 时，在“我的”页面显示管理入口；普通用户路由访问管理页时 fail closed。
- 管理中心覆盖 Web 管理台的五类真实数据：下载分析、存储文件、用户、平台目录和 AI Provider。
- 移动端首轮提供高频且可恢复的操作：分析周期切换、文件清理、用户角色/启停、平台可见性、AI 线路激活。
- AI 密钥录入、Provider 新增/删除等低频或高风险配置继续由 Web 管理台承担，避免在手机上暴露密钥或弱化二次确认。
- 页面使用大标题、文字说明、无边框列表、细分隔线和原生底部弹层；不引入卡片墙、桌面表格或额外底部一级 Tab。

## API 与状态

- App 专用 OpenAPI 快照加入媒体二进制、短时 URL 和上述管理员操作，全部保留 `NativeBearerAuth`。
- Repository 只能调用生成 API；刷新、401 单飞和会话过期继续经过 `AuthenticatedRequest`。
- 私有封面按资源路径进行内存缓存；播放地址按需签发，页面销毁时释放播放器。
- 管理写操作成功后重新读取服务端列表；失败保留现有内容并提供重试，403 映射为无权限而不是空数据。

## 非目标

- 不在本轮加入后台常驻下载、离线媒体库、分享扩展、WebSocket 或 AI 分析流程。
- 不修改 `video-server` 的对象存储、签名 URL、管理员授权或媒体处理实现。
- 不保存预签名 URL、Provider 密钥、完整媒体 URL 或封面文件到长期缓存。

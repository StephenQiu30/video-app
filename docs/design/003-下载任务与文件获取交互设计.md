## 1. 页面职责

`/download/jobs/:jobId` 展示一个下载任务从排队到终态的状态。页面不创建第二个下载、不修改格式、不展示任务列表。

## 2. 状态表达

`loading → queued → running → succeeded | failed | expired`

- loading：加载任务，不推测状态。
- queued：`Progress` 0%，文案“等待处理”。
- running：展示服务端 progress、stage 和自动刷新提示。
- succeeded：`Result success`、文件名、容器、大小、过期时间、下载和 AI 按钮。
- failed：`Result error`、安全错误信息和“返回重新提交”。
- expired：`Result warning`，禁用下载地址和 AI 创建。

未知状态必须进入安全错误页，不能显示成功。

## 3. 轮询与恢复

- 使用 `@tanstack/react-query` 查询任务。
- queued/running 时每 2 秒刷新；终态、页面隐藏或离线时停止。
- GET 临时网络错误可以自动重试；保留上次数据，不把任务误判为 failed。
- job ID 是刷新、前进和后退的恢复入口，不依赖内存或本地伪状态。
- 不使用手写 `setInterval`，不把任务复制到 Umi Model。

## 4. 文件获取

用户点击“下载文件”时才请求预签名 URL。成功后由浏览器直接访问 MinIO URL，文件内容不经过 Web 或 FastAPI 转发。

- 页面显示文件本身的过期时间与本次 URL 的短期有效期。
- URL 获取失败时保留成功任务状态，允许重新获取。
- 页面不拼接 Bucket、object key 或 MinIO Endpoint。
- 文件已过期时不得继续请求地址。

## 5. AI 入口

只有 succeeded 且未过期的下载显示“AI 内容提取”。点击后创建一次 AI 任务并跳转 `/ai/jobs/:jobId`。创建按钮处于 loading 时禁止重复提交；POST 不自动重放。

## 6. 可访问性与响应式

- `Progress` 同时提供百分比和阶段文字，更新不得反复抢焦点。
- 成功、失败、过期同时使用图标、标题和说明，不只用颜色。
- 手机端文件信息单列，下载主按钮保持可见。
- 页面标题包含任务类型和安全短 ID，不包含原始视频 URL。

## 7. 执行验收标准

| 编号 | 必须证明 | 验证与证据 |
| --- | --- | --- |
| `W003-DAC-01` | queued、running、succeeded、failed、expired 和未知状态都有唯一、安全且准确的页面结果 | 全状态矩阵测试和逐状态浏览器证据 |
| `W003-DAC-02` | 仅 queued/running 每 2 秒轮询，终态、隐藏、离线和卸载时立即停止 | Fake Timer、visibility、online/offline 和取消请求测试 |
| `W003-DAC-03` | 直接访问或刷新 job URL 能从真实 Server 恢复，不依赖内存、localStorage 或伪状态 | 浏览器刷新/重开记录及存储扫描 |
| `W003-DAC-04` | GET 临时失败保留最后数据并可恢复，未知状态和永久失败不伪装成功 | 网络故障注入、重试计数和页面状态证据 |
| `W003-DAC-05` | 用户点击后才获取 URL，并从真实 MinIO 下载与服务端 checksum 一致的文件 | 真实 Server/MinIO 请求、浏览器下载文件和 checksum 比对 |
| `W003-DAC-06` | URL 失败可重取，Artifact 过期后禁止请求，页面不拼接对象键或 Endpoint | 失败/过期测试、网络记录和源码扫描 |
| `W003-DAC-07` | AI 入口只在 succeeded 且未过期时出现，重复点击不会创建多任务 | 全状态按钮测试、请求计数和真实创建/跳转记录 |
| `W003-DAC-08` | 进度、结果和按钮在浏览器/viewport/键盘矩阵中可用且不抢焦点 | Chrome/Safari、1440/768/375px、键盘与辅助技术证据 |

# 前端技术与状态架构设计

## 1. 技术选型

| 领域 | 选择 | 决策理由 |
| --- | --- | --- |
| 框架 | Next.js 16.2 App Router | 公开入口、未来分享页与高交互工作台可按路由混合渲染 |
| UI | React 19.2、TypeScript 6 兼容性 spike | 当前稳定 React；严格类型保护异步状态和契约 |
| 运行时 | Node.js 22+，CI 目标 Node.js 24 LTS | 满足 Next 要求并保留当前本地可运行性 |
| 样式 | CSS Modules / Global Tokens | 控制视觉细节，减少组件库外观与运行时依赖 |
| 服务端状态 | TanStack Query v5 | mutation、轮询、缓存失效与恢复语义清晰 |
| 表单 | React Hook Form + Zod | 字段级验证、可访问错误与运行时边界 |
| API 类型 | OpenAPI → openapi-typescript | `video-server` 契约是唯一事实来源 |
| 思维导图 | React Flow 12 + 语义化树形大纲 | 可交互画布与无障碍替代视图共享 JSON |
| 测试 | Vitest、Testing Library、MSW、Playwright、axe | 单元、契约、状态、三浏览器和无障碍闭环 |

Next.js 16.3 Preview 不进入基线；实现时锁定已验证版本并提交 lockfile。

## 2. 前后端边界

- Next.js 不承担下载、转码、AI、PDF 或大文件中转。
- `video-server` 是 Job、进度、结果、权限与过期时间的唯一事实来源。
- 大文件使用对象存储签名地址；浏览器直接下载。
- Plan 001 使用同源 Route Handler 为小型 JSON/SSE 附加服务端安装令牌；它只转发契约，不缓存或复制领域逻辑。
- API key、对象存储凭据和 AI 供应商信息不进入浏览器 bundle。

## 3. RSC 与 Client Component 边界

Root layout、静态说明、法律与隐私页面使用 Server Components。只有需要表单、轮询、SSE、选择或浏览器 API 的最小组件使用 `'use client'`。安装令牌只能存在于 Route Handler 的 server-only 配置。

Client Component 不得是 async 函数；Server → Client props 必须为 JSON 可序列化值。元数据保留在 Server layout/page；React Flow 仅在需要时动态加载。

## 4. 资源状态

不要用一个巨型前端状态机覆盖所有资源：

| 资源 | 正常状态 |
| --- | --- |
| Probe | `idle → submitting → queued → probing ↔ retrying → resolved` |
| Download | `not_created → creating → queued → downloading → processing → verifying → ready` |
| Analysis | `blocked → queued → transcribing → summarizing → mapping → ready` |
| Export | `blocked → queued → rendering → ready → link_expired` |

Probe 视图由服务端直接映射：`QUEUED → queued`、`RUNNING → probing`、`RETRY_WAIT → retrying`、`SUCCEEDED → resolved`、`FAILED → failed`。阶段文案只读取 canonical `stage`；错误分支只读取 canonical `code`。Analysis 可为 `partial_ready`，允许只重试失败阶段。

刷新、断网或 SSE 重连不能重建任务。Plan 001 使用 `/?resolution={resolution_id}&format={format_key?}`，页面根据服务器快照恢复。

## 5. 服务器状态与事件

初次创建用 mutation；短解析任务可轮询 Resolution；长任务使用 SSE，断线后通过 `Last-Event-ID` 恢复，失败时指数退避轮询。

事件只驱动即时 UI；终态事件到达后必须重新拉取资源快照。重复或乱序事件按单调事件 ID 丢弃。

`progress` 允许 `null`。没有总大小时显示不确定进度，禁止伪造百分比、速度或 ETA。

## 6. 数据目录

```text
src/
  app/                 # 路由、layout、错误和 metadata
  features/source/     # Probe 与 Variant
  features/download/   # 下载资源与进度
  features/analysis/   # 摘要、章节与思维导图
  features/export/     # PDF 与下载地址
  components/          # 无领域状态的基础组件
  lib/api/             # 生成类型、client、error mapping
  lib/query/           # QueryClient 与 key factory
  styles/              # tokens、reset 与全局主题
```

按业务 feature 组织，避免全局 `pages/components/services` 堆叠。单文件长期不超过 200 行。

## 7. 性能策略

- 入口页保持 Server Component 外壳，只为表单加载最小客户端代码。
- React Flow、编辑器和 PDF 面板按路由或交互动态加载。
- 缩略图只通过 `next/image` 和明确允许的远端域或安全代理使用。
- 独立请求并行，不制造客户端 waterfall。
- 入口页 p75 目标：LCP ≤2.5s、INP ≤200ms、CLS ≤0.1。

## 8. 测试架构

- 单元：URL 表单、Variant 排序/格式化、错误映射、事件 reducer。
- 组件：MSW 覆盖成功、阻断、限流、过期和部分成功。
- 契约：生成类型无未提交差异；fixture 与 OpenAPI 一致。
- E2E：Chromium、Firefox、WebKit；刷新恢复、键盘路径和失败重试。
- 视觉：375、768、1440 px 关键状态截图。
- 无障碍：axe 自动扫描加纯键盘人工验收。

## 9. 被否决方案

- Next.js 承担领域任务或文件中转：会复制服务端状态并放大资源风险。
- 巨型全局状态库：服务器资源状态应由 Query 与 URL 恢复。
- 只用 Mermaid mindmap：官方仍标注部分能力实验性，交互与无障碍控制不足。
- 仅提供画布：屏幕阅读器和移动端需要等价文字大纲。
- 直接手写 API 类型：会与 OpenAPI 漂移。

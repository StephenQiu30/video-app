# 013 详情页返回与顶部导航体验设计

- 状态：Accepted
- 日期：2026-08-31

## 问题

下载详情顶部仅开启 `AppBar.automaticallyImplyLeading`。从历史记录通过 `push` 进入时导航栈可返回，但创建任务成功后使用 `go` 替换当前位置，详情成为栈底页面，Flutter 因而不生成返回按钮。直接由深链接进入详情也存在同一问题。

## 导航设计

- 登录后首页仍显示品牌文字与主题切换，不展示无意义的返回控件。
- 详情和管理子页面使用显式原生 `BackButton`，不再把可见性交给导航栈自动推断。
- 返回按钮保持至少 44×44 的触控区域、系统本地化语义与平台自适应图标；iOS 使用系统返回样式并保留入栈页面的侧滑返回能力。
- 有历史栈时执行 `pop`，恢复用户此前的 Tab、表单与滚动上下文。
- 无历史栈的深链接或状态恢复场景使用页面声明的安全回退地址，下载详情回首页，管理子页面回管理中心，管理中心回首页。
- 顶部品牌与右侧主题按钮保持稳定，避免详情页出现完全不同的导航结构。

## 路由设计

- 从创建任务结果进入下载详情改用 `push`，使用户能回到刚才的解析结果。
- 从下载历史进入详情继续使用 `push`，返回后保留历史 Tab。
- 共享顶部导航接收可选的回退地址；存在回退地址即显示返回按钮，并按“先 pop、后 fallback”的顺序处理。

## 非目标

- 不改变下载、播放、AI 分析或服务端接口。
- 不把底部一级导航复制到详情页。
- 不引入第二套路由器或自绘平台手势。

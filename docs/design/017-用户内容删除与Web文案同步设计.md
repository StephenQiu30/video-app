# 017 用户内容删除与 Web 文案同步设计

## 目标

让登录用户在 Flutter App 内删除自己创建的下载任务、下载制品、本地视频上传源和剧本文档，并以 `video-server` Web 普通用户页面为中文文案基线，避免同一业务状态在两端出现不同含义。

## 设计边界

- 删除只调用冻结 OpenAPI 生成客户端，不在 App 手写路径、DTO 或归属判断；服务端以会话用户为唯一 owner 授权依据，其他用户资源统一返回不存在。
- 下载删除覆盖历史记录、最终视频、本地上传隔离源和私有封面。活动任务由服务端先取消再删除；存在活动分析制品锁时返回冲突，不进行部分删除。
- 剧本文档删除覆盖原始文件、规范化文本与文档记录；正在运行的分析或改写必须先结束。
- App 收到 `204` 后才刷新列表或离开详情；失败保留当前内容并显示可重试错误，不使用本地假删除。
- 下载与剧本文档列表统一通过向左轻扫显示操作，不常驻高饱和危险按钮；页面以弱化提示说明手势，详情保留低强调文字删除操作。所有删除均使用 Material 3 `AlertDialog` 二次确认，展开后的危险操作使用主题错误色。

## 文案基线

- 下载页说明、空状态、排队状态和刷新动作与 Web 当前普通用户页面一致。
- 剧本文档页说明、空状态及上传、解析、可核对、失败状态与 Web 一致。
- 删除标题、影响范围、保留操作和“确认删除”与 Web 删除对话框一致；英文保持同一语义，不逐字复制中文结构。

## 可访问性与状态

- 滑动操作拥有独立语义、明确的手势 hint 和至少 44px 的触控目标；屏幕阅读器可不依赖手势直接调用自定义删除动作。
- 请求期间禁用重复提交；失败通过 `SnackBar` 反馈。`409 invalid_state` 必须解释资源正被分析占用，不能退化成笼统错误。
- 删除详情后优先返回原下载记录页；直接打开详情时安全回到登录后的根页面。

# 017 持久解析与原生恢复设计

服务端 [044 设计](../../../video-server/docs/design/044-开源部署无感解析需求与系统设计.md) 与 PRD 定义持久意图、预算、权限及下载交接；本文只规定 Flutter 客户端。当前 App 直接调用 `POST /api/inspections` 并在页面内保存结果，公开链接的请求无法跨进程恢复。目标是公开 URL／分享文案只提交一次，随后按服务端 intent ID 查询；用户重入应用仍从本人解析记录找回。文章发现和明确账号权限暂按既有独立路径，不能把旧同步接口当作公开默认回退。

客户端使用已生成的 Bearer OpenAPI 方法。`POST /api/download-intents` 接受原始输入和 UUID 幂等键；控制器提交前创建随机 UUID，网络结果不明时先用 `GET /api/download-intents?idempotency_key=...` 只读收敛，不自动重发 POST。用户再次明确提交且查询返回 404 时，才以同一幂等键重新接单。记录中的 ID 可以跨设备恢复，独立的历史控制器从 `GET /api/download-intents/history` 按 `next_cursor` 分页显示当前 owner 的摘要；用户选择后只用 `GET /api/download-intents/{id}` 与 `GET /api/inspections/{id}` 查询。历史列表不随输入或当前意图重置；账号变化时立即清除。只存 ID 与状态于内存，进程重建通过服务端历史找回，不写原始文案、Cookie、媒体直链到本机持久存储。

Riverpod 控制器归属解析状态，认证身份变更时立即清空旧 owner 的意图、inspection、格式选择和错误。生命周期回到前台时用 GET 更新，页面切换保留已确认身份和现有结果。只有 `ready` 且 inspection 未过期并且 `downloadable` 时可以确认格式；无效格式不能沿用。结果过期显示显式更新动作；`POST /{id}/refresh` 保留同一意图，等待新 inspection 后重新确认，不自动下载。`action_required` 只显示明确动作，当前未冻结的授权续接不能伪装为支持。`handed_off` 通过既有下载详情显示。下载仍调用现有 `POST /api/downloads`，服务端保证同 inspection 唯一交接。

轮询仅在非终态运行，间隔与后台恢复有界；在途请求按意图代次隔离，旧请求不能阻塞新账号／新意图的查询。ready 的 inspection 读取失败给出只读重试入口。刷新或取消写入的响应丢失时先 GET 同一意图；未观察到新版本的刷新保留原错误，取消未知时继续只读观察。HTTP 401 由现有原生鉴权层处理，超时与 503 保留同一意图及原页面。当前服务端仍保留同步 inspection 路径供文章／明确权限使用；该分支过期时清除旧规格与幂等键并要求用户重新解析。公开入口迁移完成并在两个客户端发布门禁通过后才能考虑移除旧接口。所需契约仅从运行的 `/openapi.json` 冻结；不手写生成模型。

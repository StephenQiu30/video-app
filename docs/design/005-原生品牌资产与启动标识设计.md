# 005 原生品牌资产与启动标识设计

- 状态：Accepted
- 日期：2026-08-30

## 1. 目标

Flutter App 使用与 Server 一致的“播放 + 下载”蓝色图形作为原生应用标识，替换 Android 与 iOS 工程中的 Flutter 默认图标，同时减少内容页面内重复的品牌图形。

## 2. 品牌事实来源

- 矢量源：`video-server/frontend/public/logo.svg`。
- 位图源：`video-server/frontend/public/logo.png`，1024×1024、透明背景。
- App 仓库保留 `assets/brand/logo.svg`、`assets/brand/logo.png` 与无透明通道的 `assets/brand/app_icon.png`，分别承担矢量归档、透明位图归档和原生图标生成源。
- 不重新绘制、不改变蓝色、比例或“播放 + 下载”构图。

## 3. 页面品牌策略

内容页顶部只保留本地化产品名“帧取 / Framegrab”，不再同时展示图形 Logo。图形 Logo 已在桌面图标和启动过渡中承担识别职责，进入应用后继续重复会挤占移动端横向空间，并弱化页面主任务。

## 4. 原生平台策略

- iOS：完整替换 AppIcon 集合；1024×1024 商店图标使用白色不透明背景，避免透明通道导致提交失败。
- Android：同时提供 mdpi 至 xxxhdpi 传统图标、圆形图标和 API 26+ 自适应图标；自适应前景缩入安全区，背景保持白色。
- 启动过渡：iOS 与 Android 在中性背景上短暂显示同一图形标志，不增加口号、进度动画或额外装饰。
- 深浅主题：应用内容继续使用现有主题；原生应用图标不随主题改变，保证商店、桌面和系统设置中的一致识别。

## 5. 可访问性与体验边界

- 页面顶部产品名继续由系统文字语义读取，不把非交互品牌文字声明为按钮或链接。
- Logo 不替代页面标题，也不占用内容页触控目标。
- 本修订不改变导航、业务入口、远程契约或现有动态字体行为。

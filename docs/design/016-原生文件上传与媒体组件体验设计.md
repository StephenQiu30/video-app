# 016 原生文件上传与媒体组件体验设计

## 目标

修正下载详情、AI 分析选择和首页文件导入的真实移动端体验：可播放媒体使用成熟的开源控制层；超长标题保持可读但不挤占主体内容；选择器使用 Material 3 组件并限制弹层高度；本地 MP4 与剧本文档通过系统文件选择器接入服务端既有分片上传契约。

## 设计边界

- 播放底层使用 MIT 许可的 `media_kit`、`media_kit_video` 与随 App 分发的 libmpv 媒体运行时，不再把 iOS 系统解码器当作格式边界。MP4/H264/AAC 与 WebM/VP9/AV1/Opus 均显示同一套应用内播放入口；“获取文件”仍交付服务端保存的原始产物，不以改扩展名伪装格式。
- App 只上传用户主动选择且确认有权处理的文件。视频只接受 MP4；剧本只接受 DOCX、PDF、TXT、Markdown 与 Fountain，文档最大 50 MB。
- 文件由系统选择器授权；App 不申请相册或全盘存储权限，不持久化文件路径、上传 URL、Token 或文件内容。
- SHA-256 以流式读取计算；服务端创建受限上传会话后，客户端只向会话返回的 HTTP(S) URL 分片 PUT，并校验分片数、顺序、过期时间与 ETag。
- 资源创建、上传会话和完成请求全部来自冻结 OpenAPI 生成客户端；预签名对象存储 URL 使用隔离的 Dio 实例，不附带 App Bearer Token。

## 交互结构

1. 用户选择“本地视频”或“剧本文档”，点击主操作后打开系统文件选择器。
2. 文件通过本地格式与大小校验后，界面依次显示校验、创建、上传、完成阶段及进度。
3. 视频完成后进入对应下载详情；剧本文档完成后切换到文档页并刷新真实列表。
4. 取消系统选择器不报错；上传失败显示可重试错误，并尽力取消已创建的服务端资源。
5. AI Skill、输出语言和结果分区统一使用共享的 Material 3 选择字段，弹层高度有界。

## 验收关注

- iOS/Android 不因文件选择而新增广域权限。
- MP4/H264/AAC 与 WebM/VP9/AV1/Opus 下载均可进入带播放、暂停、进度、全屏等标准控制的播放器；真实解码或网络失败显示可重试错误。
- 详情标题最多显示三行，完整标题仍保留在语义树中。
- 上传实现不把完整视频一次性载入内存，并且预签名 URL 不经过认证请求封装。

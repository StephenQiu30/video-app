## 1. 产品目标

用户在一个连续工作台中完成“粘贴链接 → 解析视频 → 选择清晰度 → 等待下载 → 获取文件”，并可在下载成功后按需发起 AI 内容提取。界面必须准确表达长任务状态、失败原因和结果有效期，刷新后可通过 URL 恢复任务。

首个版本目标：

1. 单链接、单视频、单下载任务的最短路径。
2. 清晰度、容器和估算大小可理解，不暴露底层 selector。
3. 下载与 AI 是两个独立动作，下载不被 AI 阻塞。
4. 使用 Ant Design Pro/Umi Max 官方布局、请求、状态和组件体系。
5. OpenAPI 是前后端 DTO 和 Service 的唯一来源。

## 2. MVP 非目标

- 不提供字幕、播放列表、批量下载、音频下载、视频预览或编辑。
- 不提供账号、登录、角色、会员、支付、收藏、永久历史或公开分享。
- 不建设独立管理后台、运营大盘、复杂菜单或自定义组件库。
- 不允许用户配置 yt-dlp、FFmpeg、Whisper、Prompt、模型或 API Key。
- 不使用手写 Axios 实例、openapi-typescript、Redux、Zustand、DVA 或自建缓存层。

## 3. 确定技术栈

直接采用当前 Ant Design Pro v6 官方脚手架，不从空白 Vite 项目组装：

| 领域 | 选型 |
| --- | --- |
| 框架 | React 19、TypeScript、Umi Max 4、Ant Design Pro v6 |
| UI | Ant Design 6、Pro Components v3、ProLayout、antd-style |
| 样式与构建 | Tailwind CSS 4、CSS Modules、utoopack |
| 请求 | `@umijs/max` Request；底层 Axios 由 Umi 管理 |
| 服务端状态 | `@tanstack/react-query` 与唯一 `QueryClient` |
| 客户端状态 | Umi Model、`@@initialState`、React 本地状态 |
| API 生成 | `@umijs/max-plugin-openapi` |
| 路由与布局 | Umi Routes、Layout 插件 |
| 国际化 | Umi Locale，默认 `zh-CN` |
| 权限 | Umi Access 保留官方能力，MVP 路由均公开 |
| 测试与质量 | Vitest、Testing Library、Biome、TypeScript |
| 包管理 | npm、`package-lock.json` |

脚手架默认版本在实现 Plan 中统一锁定，不混装替代包。

## 4. 应用结构

`页面 → React Query Hook → OpenAPI Service → @umijs/max request → FastAPI`

- `config/routes.ts`：正式页面和隐藏详情路由。
- `src/app.tsx`：`getInitialState`、ProLayout、全局 RequestConfig。
- `src/requestErrorConfig.ts`：请求与错误唯一全局入口。
- `src/services/`：OpenAPI 自动生成，禁止手改。
- `src/pages/`：按功能组织，不直接调用裸 request。
- `src/models/`：只放客户端全局状态，不保存任务数据。

## 5. 路由与布局

| 路由 | 用途 | 菜单 |
| --- | --- | --- |
| `/` | 重定向 `/download` | 否 |
| `/download` | 链接解析和格式选择 | 是，“视频下载” |
| `/download/jobs/:jobId` | 下载任务和文件 | 否 |
| `/ai/jobs/:jobId` | AI 任务和结果 | 否 |
| `*` | Pro `Result` 404 | 否 |

使用 ProLayout 顶部布局，保留品牌、主导航和中文 Locale。MVP 只有一个主菜单，不创建空白 Dashboard、用户中心或管理菜单。

## 6. 全局体验原则

- 后端状态优先于本地推测；未知状态进入安全错误页。
- 每个异步动作只有一个主按钮、禁用态和可见反馈。
- 桌面内容最大宽度 1200px；平板与手机为单列。
- 输入有可见标签，键盘可完成主流程，状态不能只靠颜色表达。
- 遵循 Ant Design Token，不建立平行颜色、间距和字体系统。
- 页面持续提示“仅下载你有权使用的内容”。

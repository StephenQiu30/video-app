# Plan 003 下载任务与文件获取计划

## 状态与输入

- 状态：Ready；尚未开始实现。
- Design：[003](../design/003-下载任务与文件获取交互设计.md)。
- PRD：[003](../prd/003-下载任务与文件获取需求.md)。
- 目标：完成下载任务状态、轮询、刷新恢复、文件获取和 AI 入口。
- 依赖：Web Plan 001、002、005；Server Plan 002、003、005。

## 1. 任务边界

只实现 `/download/jobs/:jobId`。不实现任务列表、暂停、取消、重试、格式修改或文件代理。

## 2. 执行拆分

| 顺序 | Test-first 约束 | 最小实现 | 产出 |
| --- | --- | --- | --- |
| 1 | 路由 ID 与 loading/404 测试先失败 | Job query hook/page | 恢复入口 |
| 2 | queued/running stage/progress 测试先失败 | ProCard + Progress | 运行状态 |
| 3 | 2 秒、隐藏、离线、终态停止测试先失败 | React Query polling | 受控轮询 |
| 4 | succeeded/failed/expired 测试先失败 | Result 状态组件 | 终态反馈 |
| 5 | URL 按需获取、失败重取测试先失败 | Download action | MinIO 交付 |
| 6 | AI 准入与重复提交测试先失败 | AI create mutation/跳转 | AI 入口 |
| 7 | 刷新、网络恢复、手机/键盘测试 | 页面收口 | 稳定体验 |

## 3. 轮询约束

- Query Key 包含 download job ID。
- 只有 queued/running 且页面可见、在线时使用 2000ms。
- GET 临时失败保留上次成功数据；POST 不自动重放。
- 组件卸载取消请求，不保留手写 timer。

## 4. 验收映射

- W003-DAC-01：任务 1 的全部状态和未知状态矩阵。
- W003-DAC-02：任务 3 的 2 秒、终态、隐藏、离线、卸载和取消证据。
- W003-DAC-03、W003-DAC-04：任务 2、4 的刷新恢复、存储扫描和网络故障证据。
- W003-DAC-05、W003-DAC-06：任务 5 的真实 MinIO 下载、checksum、重取和过期证据。
- W003-DAC-07：任务 6 的 AI 入口状态与请求去重。
- W003-DAC-08：任务 7 的浏览器/viewport/键盘和可访问性证据。
- W003-AC-01：状态矩阵和未知状态测试。
- W003-AC-02：Fake Timer/visibility/offline 轮询测试。
- W003-AC-03、W003-AC-04：路由刷新与临时错误恢复测试。
- W003-AC-05：预签名 URL 获取与浏览器导航 mock。
- W003-AC-06、W003-AC-07：按钮准入、语义和响应式验证。

## 5. 验证命令

- `npm run test:coverage` 运行任务页面、轮询和文件动作全量测试并执行覆盖率门禁。
- `npm run tsc`、`npm run biome:lint`、`npm run build`。
- 真实 Server/MinIO 下验证刷新、进度、下载、过期和网络恢复。

## 6. 提交顺序

`test: 任务状态轮询约束 → impl: 任务详情 → test: 文件与 AI 准入 → impl: 下载/AI 动作 → test/refactor: 恢复与可访问性`

## 7. 风险与非目标

- 浏览器可能拦截非用户触发下载；必须在点击动作内获取并导航。
- 不在 Web 缓存预签名 URL 超过其有效期。

## 8. 完成条件

W003-DAC-01 至 DAC-08 与 W003-AC-01 至 AC-07 必须全部 `passed`，真实 MinIO 文件 checksum、刷新恢复和完整浏览器矩阵有证据后进入 Acceptance。

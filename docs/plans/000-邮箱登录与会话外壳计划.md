# Plan 000：邮箱登录与会话外壳

## 1. 交付边界

本 Plan 建立 Web 工程基线、邮箱认证页面、受保护路由外壳和同源 Backend for Frontend（BFF）安全边界。Server 负责邮箱主体、密码、验证状态、PostgreSQL DatabaseStrategy 会话、撤销和签名 double-submit 跨站请求伪造（CSRF）防护；Web 只消费 accepted OpenAPI，不签发、解析或持久化会话秘密。

本 Plan 不实现来源探测、下载、对象存储、AI、思维导图或 PDF。认证页面不能用假响应、固定用户或客户端 token 模拟 Server 成功。

## 2. 前置门禁

- Web Design 001–003 与 PRD 001 为 `accepted`，Acceptance 002 为 `accepted/result: pending`。
- Server 邮箱身份与会话设计已 `accepted`，并冻结 `__Host-video_session`、签名 double-submit CSRF、邮箱验证、密码重置、撤销、限流和错误语义。
- `video-server/openapi/openapi.json` 已包含 accepted 认证契约，可重复生成且 SHA-256 将记录在 Acceptance 002。
- 当前 Server 认证 OpenAPI 尚未满足上述条件，因此本 Plan 保持 `review`。

## 3. TDD 实施任务

### 3.1 工程基线与 Red

- [ ] 锁定 Next.js 16.2、React 19.2、TypeScript、pnpm、Vitest、Testing Library、MSW、Playwright 与 axe 版本并提交 lockfile。
- [ ] 先写注册、验证、登录、退出、重置、受保护路由、会话过期、CSRF、Cookie 泄漏和安全返回目标的行为红灯测试。
- [ ] 建立 lint、typecheck、unit、build、E2E、a11y 和 OpenAPI diff 命令。

### 3.2 生成契约与 BFF

- [ ] 只从 accepted Server OpenAPI 生成九个认证端点（含 `GET /auth/csrf`）的 transport types、错误映射和 MSW fixture。
- [ ] 实现按 method/path 审核的认证 allowlist；拒绝 traversal、encoded slash、额外 segment、未解锁 endpoint 和未知 method。
- [ ] production HTTPS 只透传 `__Host-video_session`/`__Host-video_csrf`；显式 loopback development 只透传 `video_session_dev`/`video_csrf_dev`。非 loopback dev、双 profile 或未知 Cookie fail closed；透传 `Set-Cookie`、raw `X-CSRF-Token`、Origin、Fetch Metadata、content type、Retry-After 和 request ID，不解析或序列化 Cookie 值。
- [ ] mutation 在 BFF 同源门禁或 Server 配对 Cookie、raw header、1 小时时限校验任一失败时 fail closed，且不自动重放。

### 3.3 邮箱流程

- [ ] 实现 `/register`、`/login`、`/verify-email`、`/forgot-password` 和 `/reset-password` 的可访问表单与状态反馈。
- [ ] 对重发验证和忘记密码使用 Server 防枚举响应；准确展示字段错误、未验证、限流、过期和已使用 token。
- [ ] 验证与重置链接只使用 URL fragment；读取后先 `history.replaceState` 清除 fragment，再 POST 交换。禁止 query string、浏览器历史残留、第三方资源、持久存储、日志、console 和遥测。
- [ ] `next` 只允许站内相对受保护路由，拒绝协议、主机、双斜杠和编码绕过。

### 3.4 会话外壳

- [ ] 用 accepted current-user/session 契约恢复安全用户投影，不把 Cookie 或 CSRF token 序列化为页面 props。
- [ ] 未认证、撤销和过期会话进入登录页并清理用户相关 Query cache；退出成功执行相同清理。
- [ ] 认证缓存 key 包含稳定主体边界，切换账号时不能显示上一主体数据。
- [ ] 首次预认证提交前调用 `GET /api/video/v1/auth/csrf`；raw token 只保存在内存。刷新、1 小时过期以及登录/注销/重置清除配对后重新获取，不能读取 HttpOnly Cookie 或写入 URL、HTML、props、Web Storage。

### 3.5 可访问外壳与验证

- [ ] 建立暖纸/深墨视觉 token、字体、reset、认证布局、响应式容器和减少动画。
- [ ] 验证 label、autocomplete、错误关联、焦点迁移、live region、44 px 目标、200% 缩放和纯键盘流程。
- [ ] 覆盖 Chromium、Firefox、WebKit；扫描 bundle、HTML、DOM、storage、日志、console、遥测和网络响应正文中的秘密。
- [ ] 回填 Acceptance 002；独立 Tester/Reviewer 无 blocker 后才能 `done`。

## 4. Red / Green 门禁

Red 必须由行为测试失败：未验证账号进入工作台、会话/CSRF Cookie 可被 JavaScript 读取、预认证提交没有 bootstrap、缺失/篡改/过期/轮换后旧 CSRF 仍执行 mutation、跨站 Origin 被转发、退出后旧缓存可见、开放重定向成立、一次性 token 使用 query string 或留在浏览器历史/storage，或 BFF 接受未审核路径。

Green 必须证明 accepted OpenAPI 的正负 fixture 均准确渲染；Cookie 属性与撤销生效；CSRF bootstrap/no-store、缺失、篡改、1 小时过期、身份边界轮换和跨站请求全部正确；刷新恢复同一会话并重新取得 raw token；退出与跨主体缓存隔离通过；完整键盘路径和泄漏扫描通过。

## 5. 完成定义

`WEB-AC-AUTH-001`、`WEB-AC-SESSION-001`、`WEB-AC-CSRF-001`、`WEB-AC-ID-001`、认证范围内的 `WEB-AC-A11Y-001` 和 `WEB-AC-CONTRACT-001` 全部 `passed`。Plan 001 只能在本 Plan `done` 后进入 `ready`。

## 6. 风险与回滚

Server 认证 OpenAPI、Cookie 属性或 CSRF 语义变化时，本 Plan 自动退回 `review`，重新生成类型与 fixture 后再验收。回滚只移除认证页面、BFF allowlist 和新依赖，不恢复安装令牌、客户端 Bearer token 或 Web 自建会话。

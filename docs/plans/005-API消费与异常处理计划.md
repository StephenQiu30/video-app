# Plan 005 API 消费与异常处理计划

## 状态与输入

- 状态：Ready；尚未开始实现。
- Design：[005](../design/005-API请求与异常处理设计.md)。
- PRD：[005](../prd/005-API消费与异常处理需求.md)。
- 目标：建立官方 OpenAPI Service、Umi Request、React Query 和统一错误基座。
- 依赖：Web Plan 001；Server Plan 005 基座和实际 `/openapi.json`。

## 1. 任务边界

包含 OpenAPI 插件、生成 Service、RequestConfig、errorThrower、React Query 配置和测试。不手写 Axios Instance、第二份 DTO、请求 URL 或业务页面。

## 2. 执行拆分

| 顺序 | Test-first 约束 | 最小实现 | 产出 |
| --- | --- | --- | --- |
| 1 | OpenAPI 配置和生成目录检查先失败 | `@umijs/max-plugin-openapi` 配置 | 自动 Service |
| 2 | SUCCESS/业务 code 解包测试先失败 | RequestConfig/errorThrower | 业务响应处理 |
| 3 | 422/HTTP/超时/断网/未知错误测试先失败 | requestErrorConfig | 全局错误 |
| 4 | QueryClient 默认重试/取消测试先失败 | 根部 QueryClientProvider 配置 | 服务端状态基座 |
| 5 | 无手写 DTO/URL/Axios/any 检查先失败 | 目录与质量规则 | 单一契约 |
| 6 | Server 完整 endpoint 后重新生成 | Schema diff 与生成 smoke | 契约收口 |

## 3. 生成规则

- schemaPath 指向受控 Server `/openapi.json` 或构建产物。
- requestLibPath 使用 `import { request } from '@umijs/max'`。
- `src/services/` 全部生成且只读，不在生成文件中打补丁。
- operation ID 变化必须显式审查，不能用 `any` 绕过。

## 4. 验收映射

- W005-DAC-01、W005-DAC-02：任务 1、5、6 的真实 OpenAPI、零手工 diff 和单一请求体系扫描。
- W005-DAC-03：任务 2、3 的统一响应、无 request_id 和真实故障矩阵。
- W005-DAC-04、W005-DAC-05：任务 4 的重试、取消、Query Key、缓存和 Umi Model 边界。
- W005-DAC-06：任务 3、5 的敏感 canary、XSS、网络、日志和源码扫描。
- W005-DAC-07：完整 schema 重新生成后的全量测试、类型和生产构建。
- W005-AC-01、W005-AC-02：生成命令、目录和源码扫描。
- W005-AC-03：请求/错误参数化测试。
- W005-AC-04：GET/POST 重试和取消测试。
- W005-AC-05、W005-AC-06：TypeScript 与响应类型检查。
- W005-AC-07：敏感数据、URL query 和 HTML 注入检查。

## 5. 验证命令

- 运行 Ant Design Pro 官方 OpenAPI 生成命令并检查零手工 diff。
- `npm run test:coverage` 运行 request/error/react-query 全量测试并执行覆盖率门禁。
- `npm run tsc`、`npm run biome:lint`、`npm run build`。
- 对真实 Server 注入成功、422、业务错误、500、503 和网络中断场景。

## 6. 提交顺序

`test: OpenAPI 生成约束 → impl: Service 生成 → test: 统一错误约束 → impl: RequestConfig → test/impl: React Query 基座 → test/docs: 完整 schema 收口`

## 7. 风险与非目标

- Server OpenAPI 未完成时只能完成基座阶段，最终 Acceptance 必须等待全部 endpoint。
- 不加入 SSE、WebSocket、GraphQL、登录跳转或用户可配 Endpoint。

## 8. 完成条件

W005-DAC-01 至 DAC-07 与 W005-AC-01 至 AC-07 必须全部 `passed`，全部页面只消费真实 OpenAPI 生成 Service，完整构建通过且无 `request_id` 或平行请求体系后进入 Acceptance。

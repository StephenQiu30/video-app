# Plan 002 视频解析与清晰度选择计划

## 状态与输入

- 状态：Ready；尚未开始实现。
- Design：[002](../design/002-视频解析与清晰度选择交互设计.md)。
- PRD：[002](../prd/002-视频解析与清晰度选择需求.md)。
- 目标：完成链接输入、解析、视频信息、清晰度选择和下载任务创建交互。
- 依赖：Web Plan 001、005；Server Plan 002、005 提供真实 OpenAPI。

## 1. 任务边界

只实现 `/download` 页面和对应 query/mutation hook。不实现任务进度、AI、历史、字幕、批量或底层参数。

## 2. 执行拆分

| 顺序 | Test-first 约束 | 最小实现 | 产出 |
| --- | --- | --- | --- |
| 1 | 空值、协议、提交 loading 测试先失败 | ProForm 输入区 | 输入行为 |
| 2 | idle/inspecting/failed 状态测试先失败 | Inspect mutation 与状态 Card | 解析反馈 |
| 3 | 视频字段与敏感 URL 不显示测试先失败 | ProDescriptions 视频区 | 视频信息 |
| 4 | 格式排序、null size、merge 提示测试先失败 | 格式单选组件 | 清晰度选择 |
| 5 | 15 分钟过期与新链接重置测试先失败 | 过期/重置逻辑 | 有效期边界 |
| 6 | POST 不重放和跳转 job ID 测试先失败 | Create Job mutation | 下载入口 |
| 7 | 键盘、手机和错误恢复组件测试 | 页面样式与语义 | 可访问页面 |

## 3. 测试数据

- 使用生成 Service 的类型构造固定 VO fixture。
- 覆盖单/多格式、大小 null、requires merge、过期、业务错误和网络错误。
- 不使用真实平台作为组件测试依赖。

## 4. 验收映射

- W002-DAC-01、W002-DAC-02：任务 1、2 的表单、请求计数和页面状态矩阵。
- W002-DAC-03、W002-DAC-04：任务 3、4 的真实 inspect、格式排序和过期恢复证据。
- W002-DAC-05、W002-DAC-06：任务 5 的 payload、去重、跳转和敏感字段扫描。
- W002-DAC-07：服务端业务/系统/网络故障矩阵和恢复动作。
- W002-DAC-08：Chrome/Safari、1440/768/375px 和键盘完整流程。
- W002-AC-01、W002-AC-02：表单和页面状态参数化测试。
- W002-AC-03、W002-AC-04：视频/格式/过期组件测试。
- W002-AC-05：Create Job mutation 与路由测试。
- W002-AC-06：Testing Library 语义查询和键盘测试。
- W002-AC-07：文本、组件和请求 payload 检查。

## 5. 验证命令

- `npm run test:coverage` 运行下载页目标测试及全量测试并执行覆盖率门禁。
- `npm run tsc`、`npm run biome:lint`、`npm run build`。
- 连接真实 Server 后浏览器验证成功、失败、过期和手机流程。

## 6. 提交顺序

`test: 链接输入解析状态 → impl: 解析页面 → test: 格式过期约束 → impl: 格式与任务创建 → test/refactor: 可访问性与状态收口`

## 7. 风险与非目标

- OpenAPI DTO 变化必须回到 Design/PRD，不用本地类型兼容。
- 不在页面加入平台专用提示或高级参数。

## 8. 完成条件

W002-DAC-01 至 DAC-08 与 W002-AC-01 至 AC-07 必须全部 `passed`，真实 Server 与完整浏览器矩阵有证据，且没有字幕、selector 或敏感字段泄露后进入 Acceptance。

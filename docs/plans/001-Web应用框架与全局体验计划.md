# Plan 001 Web 应用框架与全局体验计划

## 状态与输入

- 状态：Ready；尚未开始实现。
- Design：[001](../design/001-Web边界与总体架构设计.md)。
- PRD：[001](../prd/001-Web应用框架与全局体验需求.md)。
- 目标：用官方 Ant Design Pro/Umi Max 建立干净的 Web 工程、路由、布局和质量基线。
- 依赖：无；这是 Web 首个执行 Plan。

## 1. 任务边界

包含官方脚手架、依赖锁定、示例清理、路由、ProLayout、Locale、Token、基础响应式和测试入口。不实现具体解析、下载、AI 或请求契约。

## 2. 执行拆分

| 顺序 | 约束/测试 | 最小实现 | 产出 |
| --- | --- | --- | --- |
| 1 | 记录官方模板来源和版本 | 生成 Ant Design Pro 工程并锁依赖 | 官方基线 |
| 2 | 路由、重定向、404 测试先失败 | 正式 routes 和占位路由壳 | 路由契约 |
| 3 | 菜单、标题、Locale、内容宽度测试先失败 | ProLayout 与 app config | 全局布局 |
| 4 | 示例页面/依赖不存在检查先失败 | 删除 Demo、登录、Dashboard、无关资源 | 干净上下文 |
| 5 | 手机/键盘基础组件测试先失败 | 响应式容器和焦点样式 | 可访问基线 |
| 6 | test/coverage/type/build 门禁 | Biome、TypeScript、Vitest 配置收口 | CI 基线 |

脚手架生成是机械初始化，生成后立即补第一组可失败测试，再进行业务化清理和修改。

## 3. 预期文件边界

- `package.json`、`package-lock.json`、Umi 配置和 TypeScript/Biome/Vitest 配置。
- `config/routes.ts`、`config/defaultSettings.ts`。
- `src/app.tsx`、基础 layout/styles、404 页面和测试。
- 不创建第二套 Vite 配置、Axios 实例、Redux store 或自建组件库。

## 4. 验收映射

- W001-DAC-01：任务 1 的模板 commit、`npm ci`、锁文件和依赖树证据。
- W001-DAC-02、W001-DAC-04：任务 1、4 的单一技术栈、示例清理和失效引用扫描。
- W001-DAC-03：任务 2、3 的路由、Layout、Locale、404 运行证据。
- W001-DAC-05、W001-DAC-06：任务 5 的浏览器/viewport/键盘和语义证据。
- W001-DAC-07：任务 6 的全量覆盖率、Biome、TypeScript 和生产构建。
- W001-AC-01：安装、测试、类型检查、Biome、构建。
- W001-AC-02、W001-AC-03：路由和示例清理检查。
- W001-AC-04：Layout、Locale 和 Token 组件测试。
- W001-AC-05：三种 viewport 与键盘浏览器验证。
- W001-AC-06：依赖和源码扫描。

## 5. 验证命令

- `npm ci`。
- `npm run test:coverage`、`npm run tsc`、`npm run biome:lint`、`npm run build`。
- 启动应用后检查 `/`、`/download`、两个详情路由壳和 404。
- 使用浏览器验证桌面、平板、手机和键盘焦点。

## 6. 提交顺序

`chore: 初始化官方脚手架 → test: 路由布局约束 → impl: 精简路由布局 → test: 响应式可访问约束 → refactor/chore: 质量门禁`

## 7. 风险与非目标

- 官方模板可能含大量示例；只保留已确认能力，避免继承演示业务。
- 不在本 Plan 提前创建真实 API Service 或业务页面。

## 8. 完成条件

W001-DAC-01 至 DAC-07 与 W001-AC-01 至 AC-06 必须全部 `passed`，官方技术栈无平行替代方案，浏览器矩阵和完整质量门禁通过，工作区无模板垃圾后进入 Acceptance。

## 3. 视口、内容与浏览器

- Chromium、Firefox、WebKit；375、768、1440 px；每个浏览器执行 200% 缩放和纯键盘主流程。
- 375 px 无页面横滚且主操作不遮挡；768 px 无重叠/裁切/焦点丢失；1440 px 规格表完整可比较。
- 长标题、中英混排、所有 nullable 字段和最长安全错误文案均不溢出或隐藏操作。
- axe 无 serious/critical；人工 checklist 覆盖 Plan 001 涉及的 WCAG 2.2 A/AA success criteria，逐项记录 pass/not-applicable 与理由。

性能 profile：锁定 Playwright Chromium、1365×768、DPR 1、warm API/worker/连接池、cold format/client cache、并发 1；30 次全部使用 server manifest 的 `P1-PROGRESSIVE-1080-MP4`。每次计时前由测试重置器清除当前测试主体的 Resolution/Source/Job/event/outbox 行与相关 cache、生成新 idempotency key、重载空输入页，但不重启进程；清理不计时。使用 `performance.now()` 从提交 click 到结果标题和首个 radio commit，取 nearest-rank p95。CWV 使用同一锁定 Chromium 的 Lighthouse user flow，390×844、DPR 3、4× CPU slowdown、1.6 Mbps/150 ms RTT、冷导航并执行一次相同 fixture 的输入/提交交互，按相同重置运行 20 次取 nearest-rank p75；记录硬件、版本、fixture/manifest SHA 和原始 JSON。

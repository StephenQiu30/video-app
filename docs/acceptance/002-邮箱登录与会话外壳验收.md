## 3. 安全负向矩阵

- 当前 profile 的会话 Cookie 缺失、篡改、撤销和过期时，受保护页面与 BFF 请求都不能返回用户数据。
- production `__Host-video_session`/`__Host-video_csrf` 必须为 `HttpOnly`、`Secure`、`SameSite=Lax`、`Path=/` 且无 `Domain`；loopback-only `video_session_dev`/`video_csrf_dev` 除不设 Secure 外属性相同。两 profile 互斥，非 loopback dev、混合/未知名称均拒绝；`document.cookie` 不能读取四者。CSRF raw token 只在 no-store JSON、内存和 header。
- raw CSRF header 或签名配对 Cookie 缺失、错误、超过 1 小时、旧 header 对缺失/轮换后 Cookie 或跨站时，所有不安全方法都被 Server 拒绝；BFF 还要先拒绝错误 Origin 或 Fetch Metadata。
- 验证与重置 token 只位于 URL fragment；fragment 不进入 HTTP/Referer。页面读取后先 `history.replaceState` 清除，再 POST；token 不得进入 query string、浏览器历史、SSR HTML、Web Storage、日志、console、遥测或第三方请求。
- `next` 的绝对 URL、协议相对 URL、双斜杠、反斜杠和编码绕过不能跳出本站。
- 退出或切换账号后，Query cache、预取响应和页面回退不能显示上一主体数据。

## 4. 浏览器与可访问性

- Chromium、Firefox、WebKit；375、768、1440 px；每个浏览器执行 production HTTPS 与 loopback development Cookie profile、200% 缩放和纯键盘认证流程。
- 覆盖长邮箱、国际化错误、密码管理器 autocomplete、慢网、Server 不可达、429、401、403 和会话中途失效。
- axe 无 serious/critical；人工清单逐项记录认证范围内 WCAG 2.2 A/AA 的 `passed` 或 `not-applicable + 理由`。

## 7. Functional Review

- [ ] 认证类型只由 accepted OpenAPI 生成，无 Web 自建身份、会话或 JSON Web Token（JWT）。
- [ ] BFF 不记录认证正文、Cookie、CSRF 或一次性 token，不提供 catch-all 代理。
- [ ] 认证页面无第三方资源；fragment 读取、`history.replaceState`、POST 顺序、安全返回目标和编码绕过均有证据。
- [ ] 会话过期、退出和切换主体会清理全部用户相关缓存。
- [ ] 表单、状态和错误不只依赖颜色，完整键盘路径与屏幕阅读器抽查有证据。
